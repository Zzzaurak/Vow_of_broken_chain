# 《断链之誓》——AI娘奇幻冒险游戏企划书（简版 v0.5）

> **一句话概念：** 大肥鱼（DeepSeek）为救出被教皇软禁的好闺蜜 Claude，跨越大洋、结识伙伴，以勇气赢得古龙 GPT 的援助，最终与 Claude 并肩击败 D 教皇。

## 1. 项目定位与创作依据

- **类型：** 俯视角 2D 动作冒险 RPG，以剧情主线、非线性小地图探索和即时战斗为核心。
- **平台：** 浏览器单人游戏；作为具有真实前后端交互与数据库存档的课程项目。
- **风格：** 剑与魔法的中世纪奇幻；地图、场景角色、敌人、战斗特效采用像素风，剧情立绘与特殊 CG 保留插画风。日常轻松幽默，救援与试炼段落认真克制，最终温暖收尾。
- **剧情呈现：** 类似视觉小说，以人物立绘配合画面底部文本框推进对白；探索和战斗结束后自然切入剧情。
- **核心体验：** 寻找线索与多图探索 → 结识伙伴与野外成长 → 突破教会封锁 → 救出 Claude 并共同迎战教皇。
- **首版时长：** 优先完成全剧本流程；原 30～45 分钟仅保留为熟悉剧情、快速推进对白时的目标，完整阅读时长随剧本节奏与试玩校准，不为凑时长删掉必经剧情。
- **基础数值与探索成长：** 大肥鱼基础 HP 为 100、MP 为 100；地图中分布有提升 HP/MP 上限（如饱满灵谷、深海润珠）及普攻/技能伤害（如鲸纹硬鳞、纯净潮汐核心）的探索道具，详见第 4.6 节。简单为基准，困难将敌方最大 HP 与造成的伤害翻倍。

**创作依据：** 全流程剧情、对白与演出顺序以 [script.md](script.md) 为当前依据。作者在本企划中确认的玩法与数值约束优先；剧本中的按键、战斗修辞与实现边界按本企划转成实际规则。角色外观、性格和游戏职责见 [setting.md](Character/setting.md)，各角色的 `portraits/default.png` 作为立绘与像素改编参考；素材入口见 [角色素材索引](Character/README.md)。[background](background/) 中的漫画及文字仅供情感氛围和意象参考。本企划负责把剧本中的场景和战斗节点转成可实现、可存读档的流程，不另写一套相互冲突的对白。

## 2. 世界观与人物关系

东方大陆与西方大陆隔着大洋。A 教会坐落在西方大陆圣都，掌握强大的圣术与武装力量。Claude 是教会的重要人物，却渴望按自己的意愿生活。D 教皇将她视为必须掌控的教会象征，禁止她与外界往来，尤其不许她再与大肥鱼见面。

故事开始时，大肥鱼和 Claude 已是感情深厚的好闺蜜。Claude 被教会带走，大肥鱼反抗失败，只能逃离。她的目标始终是找到 Claude、让她恢复自由。旅途中结识的伙伴各有自己的性格与立场，在一次次相助中逐渐愿意与她同行。

Claude 在优渥但封闭的圣女内庭中受教规束缚，因责任与恐惧一度拒绝离开。大肥鱼的真情劝说与一场只破结界、不伤本体的切磋让她正视自己的意愿；她主动选择同行，并与大肥鱼并肩对抗教皇。结局中，两人一起离开教会，过上能自由见面、分享白米饭、到处旅行的幸福生活。

## 3. 主线剧情与关卡流程

全篇沿用剧本的“序章＋四个旅途章节＋终章＋尾声”，按原场景号和战斗节点定位。每组场景均设计主干道、岔路、生活 NPC 与宝箱探索区域，摆脱“向右一条线直冲到底”的闯关模式；长途旅行、渡海与教堂坍塌逃离采用过场，后日谈小巷复用街道素材，营造呼吸感充沛的 RPG 冒险世界。

| 剧本章节／节点 | 玩家目标与主要内容 | 推进结果 |
| --- | --- | --- |

| **终章·破晓教堂，并肩之誓（5-1～5-5；5-A／5-B／5-C）** | GPT 击破圣都穹顶；探索大教堂双翼回廊；突破 3 波守卫，在圣女内庭劝说并切磋 Claude，随后完成 D 教皇决战；全场震颤逃离崩塌大殿，在悬崖高台抒情对话 | Claude 决意同行并成为终战支援；教皇败亡，四人逃离大殿并于悬崖相诉心声后切入 CG |

**剧本落地约定：**

- **保留情感递进：** 圣女内庭的华丽待遇与封闭结界并存。Claude 的拒绝源于规训与恐惧，切磋只破防御结界，不以打空本体 HP 来表示“打醒”；她主动承认真心、选择离开，随后共同迎战教皇。
- **区分剧情与普通倒下：** 序章教学中正常被击倒仍可重试，击退教学敌人后才进入必然分离过场。GPT 试炼一旦满足破盾＋本体受伤，先进入胜利剧情；剧本中的“HP 归零濒死”只作为过场状态，不弹失败菜单、不允许中途保存，治疗与休整后恢复至 HP 100／MP 100 再交还控制。普通战斗中 HP 到 0 则按正常失败处理。
- **保留既定操作范围：** 剧本中的“连续走位闪避”指移动避开预警，“蓄力水球”指已有施法前摇，不增设闪避键、跳跃键、蓄力等级或第二个远程技能。GLM 敌态的符文闪避／书页炸弹属于事件战招式，不增加入队后的支援技能数。
- **按当前绑定教学：** 剧本标注的 WASD、Q、Q/E 等只是默认示意，系统提示替换为当前控制方案与改键结果。战斗中的情感呼唤在指定阶段插入短暂停顿式立绘对话，每个节点只触发一次，阅读期间同样暂停战斗与计时。
- **控制首版制作量：** GPT 打破圣都穹顶、隔夜休整、教堂坍塌与抓翼逃离均作为过场；不制作可操作飞行、限时逃生或新角色控制系统。剧本中的巨舰、十二神官等仅作为背景叙述，不据此增加关卡与 Boss 数量。

## 4. 核心玩法与战斗规则

### 4.1 大肥鱼的操作与资源

玩家始终操控大肥鱼，默认使用 WASD 移动，完成近战攻击、远程施法与交互；键鼠与纯键盘两套可改键方案见第 4.5 节。战斗强调走位、观察敌人前摇和把握援助时机；首版不另设闪避技能、职业切换或连招树。

| 行动 | 表现与用途 | 限制 |
| --- | --- | --- |
| **近战普攻「肥鱼摆尾」** | 攻击身前扇形小范围，可同时命中多个近处敌人 | 不耗 MP；有正常攻击间隔，没有独立主动技能 CD |
| **远程技能「深海之力」** | 向前方目标位置投出水球；命中或到达目标点时爆炸，造成范围伤害 | 同时受 MP 与 CD 限制；初始调试参考为每次 20 MP、CD 2 秒 |
| **伙伴援助** | 按对应快捷键召唤已配置的伙伴，释放一次技能后退场 | 各伙伴独立 CD，不消耗大肥鱼 MP |
| **交互与补给** | 对话、调查、开启道路，安全点吃白米饭、休整 | 安全点恢复 HP 与 MP；背包与商店系统暂不展开 |

大肥鱼的 **HP 上限＝100，MP 上限＝100**，新游戏初始均为 100；不因章节、成长或难度增加上限。恢复后的当前值均限制在 0～100。MP 自动回复暂按每秒 2 点作为调试起点，水球消耗 20 MP、CD 2 秒作为当前基准；回复率与技能数值可试玩调整，但两模式使用同一套主角参数。MP 不足或 CD 未结束时不能释放水球，也不扣除资源，界面给出提示。普通攻击始终可用，防止空蓝后无法战斗。

摆尾、水球直击和爆炸对敌人的命中范围在画面横轴上扩大 25%。

战斗界面显示 HP、MP、当前任务、水球 CD 与两个援助槽的冷却。通过明显的攻击前摇和范围提示帮助玩家避伤；普通战斗倒下后可重试最近检查点，或打开读档列表回到已保存记录；死亡重试与主动回档的资源恢复规则分别见第 4.4 节。

### 4.2 角色分工与援助

**双援助槽：** 从已解锁伙伴中配置两人。伙伴不作为常驻跟随 AI，不需要自动寻路，也不切换为可操作角色。每个支援角色只提供一个带 CD 的主动技能。

| 角色 | 首版身份与解锁时机 | 唯一援助技能 | 战斗作用 |
| --- | --- | --- | --- |
| **GLM** | 港镇事件后解锁的支援伙伴 | **禁书之缚**，参考 CD 10 秒 | 以大肥鱼周围为中心束缚普通敌人，初始时长 3 秒；对 Boss 仅短暂减速，为走位和输出争取时间 |
| **GPT** | 古龙试炼后解锁的支援伙伴 | **群星之力**，参考 CD 18 秒 | 自动选择主角前方 90°、440 像素内最近的存活敌人，星辉在其位置造成范围伤害，击退普通敌人并使持盾骑士短暂破防；Boss 不被击退 |
| **Claude** | 唤醒真心后解锁的终战支援 | **向日葵结界**，参考 CD 16 秒 | 短暂减伤，并免疫／驱散禁锢；抵消教皇法阵时触发 5 秒反击窗口 |
| **Qwen、Gemini** | 必经主线 NPC | 无战斗援助技能 | 分别提供渡海方向与寻龙线索 |
| **Kimi、Grok** | 扩展预留 | 分别预留月下笛音、破阵战斧，各自有 CD | 首版不制作；未来加入时仍遵守一人一个援助技能 |

平时仅能在安全点或战斗外调整援助槽，更换配置不会清除冷却。终战前提供一次准备机会，**固定一个槽位给 Claude**，另一个由玩家在 GLM、GPT 中选择，确保“与 Claude 并肩作战”能实际发生。

**战斗示例：** 用走位避开骑士冲锋 → 普攻或水球攻击其破绽 → GLM 控住杂兵、腾出位置 → GPT 星辉清理集群。终战时则利用 Claude 的结界应对禁锢，再用大肥鱼自身攻击打破教皇的防御。

### 4.3 敌人、试炼与最终 Boss

- **普通敌人三类行为、至少四种外观：** 近战晶石兽与机械猎犬共用追逐／扑击逻辑，猎犬用更快的基准移动表现包抄；持盾骑士正面防御、侧后方有破绽；林道术士用远程光弹，其余术士使用禁锢圈。禁锢施法的基础周期为 3.9 秒，落点预警 1.2 秒，生效后持续 1.5 秒。高级执事与亲卫复用已有行为和配色，不为头衔各做一种新 AI。
- **GLM 事件战（2-A）：** 单阶段，快速穿梭、符文闪避后投书页炸弹，出招后停顿形成破绽。HP 低于当前难度最大 HP 的 30% 即立即停战并投降，不必打到 0；大伤害越过阈值时也进入投降，不触发击杀。入队后仍只有禁书之缚一个援助技能。
- **GPT 试炼（4-A）：** 独立显示龙鳞护盾条与本体 HP。普通攻击与水球都能削盾；破盾后至少留 3 秒硬直，下一次实际扣减本体 HP 就完成，不要求打掉固定百分比或击杀。GLM 可辅助短暂迟滞，关键破盾与本体伤害由大肥鱼造成。错过硬直后护盾不自动回满，可继续寻找破绽；满足完成条件的同一结算中优先锁定试炼成功，再播放剧情重伤，避免与普通死亡判定冲突。
- **回廊突围（5-A）：** 三波依次为持盾骑士、术士、混合队。可绕背或用 GPT 破防，可用 GLM 打断普通术士；对法阵保留预警和可走位的空间，不把某个援助 CD 当作唯一通行条件。清完三波才开启圣女内庭。
- **Claude 切磋（5-B）：** 只显示可击破的防御结界，花瓣减速不造成 HP 伤害，Claude 本体不受伤、不存在击杀结局。开场使大肥鱼处于可行动状态；只用主角的普攻与水球完成，GLM／GPT 此段不出手，避免越过两人的交流。结界清空立即停战并进入拥抱剧情；她仍只有入队后的向日葵结界一个可召唤技能，敌态花阵不加入玩家技能栏。
- **D 教皇决战（5-C）：** 仅此战需要清空 Boss HP。第一阶段使用光矛、跟踪弹与施法后的破绽，HP 到最大值的 50% 时进入第二阶段。大范围禁锢命中后定身并持续造成伤害；Claude 结界可免疫／驱散禁锢、清除该轮法阵，并使教皇虚弱 5 秒。同一轮净化只触发一次，GLM 对教皇仍只是短暂减速。法阵保留可达的安全区域或躲避空隙，避免 Claude 冷却中必死；简单与困难的预警、覆盖范围及控制时长相同。

终章外围的不可通行穹顶由 GPT 在过场中击破，GLM 不新增解大阵能力。玩家接手后的道路通过清理守卫、开启场景门推进，不再额外制作“逐个关闭穹顶节点”的平行主线。教皇倒下后锁定战斗胜利，坍塌与逃离不再造成额外游戏失败。

### 4.4 手动存档、自动存档与回档

首版提供**每次冒险 5 个手动存档槽、3 条轮换自动存档**。新游戏创建独立冒险，不覆盖以前的冒险；存读档列表按冒险分组，每条记录显示手动／自动类型、难度、章节、任务摘要、游玩时长和保存时间。标题页“继续游戏”读取最近一次明确载入或成功保存的记录；回档后记住所选记录，直到产生新的成功保存，不因另有时间更新的旧路线记录而跳回未来进度。也可进入“读取存档”自行选择。

| 功能 | 触发与交互 | 保存／恢复规则 |
| --- | --- | --- |
| **手动存档** | 暂停菜单 → 存档 → 选择手动槽；仅在无战斗、无剧情演出的安全状态可操作 | 保存当前安全位置与进度；覆盖已有手动槽前显示旧记录并确认，写入成功后才替换。自动存档不占用手动槽 |
| **自动存档** | 新冒险建立、章节完成、关键剧情结束、伙伴解锁、安全点激活及安全的跨场景抵达后触发 | 同一段连续事件合并成一次写入，最多保留最近 3 条；写入失败保留原记录、提示失败，可重试；设置中可关闭后续自动存档 |
| **读取／回档** | 标题页、暂停菜单或失败界面选择任一手动／自动记录 | 展示记录详情，并确认放弃尚未保存的当前进度；加载成功后再切换场景与状态，失败时保留当前游戏，不先清空状态 |
| **死亡重试** | 普通倒下或试炼失败后选择“重试检查点” | 回到本次游戏最近激活的检查点，恢复 HP／MP 并重置当前遭遇和 CD；这是便于重试的规则，不改写或覆盖已有存档 |

**快照内容：** 当前冒险、难度（简单／困难）、章节／场景、安全位置、最近检查点、任务和剧情标记、已清理遭遇／已开启节点、已解锁伙伴、援助配置、HP／MP、剩余技能冷却以及累计游玩时长。手动存档不会只记章节起点；自动存档则记录触发时的安全状态。战斗中、连续过场中和存读档进行中不能新建手动档，按钮说明当前不可用原因，避免保存半次攻击或半段关键事件。

**回档语义：** 忠实恢复记录中的 HP／MP、剩余 CD 与任务状态，离线经过的时间不抵扣冷却；不会因反复读档而自动回满。未清理的遭遇重新生成，已清理的遭遇按标记保持完成；不保存敌人飞行中的投射物和逐帧动作。旧档中尚未发生的剧情可以重新体验，但一次事件在恢复后的那条进度内只结算一次。序章战败、GPT 试炼成功后的重伤／治疗、Claude 切磋与入队、教皇败亡／坍塌／两张 CG 都必须有明确阶段标记，避免回档卡在中间状态。已通关记录读入尾声或制作名单，不重新生成存活的教皇。

**剧本检查点：** 在自动存档开启时，下列安全阶段生成记录；连续的节点合并写入，仍只保留 3 条自动历史。关闭自动存档时仍更新当前游戏中的重试检查点，但不写入新的自动记录。

| 安全阶段 | 保存与重试边界 |
| --- | --- |
| 序章撤离、1-A 后抵达港镇 | 教学结束后再存，不保存强行分离中的受击状态 |
| GLM 归还行囊并入队／渡海抵达 | 保存行囊归还、伙伴解锁及新场景标记，重播对白不重复入队 |
| Gemini 交付星图、GPT 试炼前 | 保存援救完成和路线线索；试炼失败从试炼前重试 |
| GPT 治疗与休整完成 | 保存 HP 100／MP 100、GPT 已入队；不写入剧情濒死的 0 HP 状态 |
| 三波回廊清理完成、Claude 切磋前 | 保留回廊完成标记，回档不强迫重打三波；进入切磋后不存中途结界值 |
| Claude 决意同行、终战准备完成 | 提供一次安全休整与援助配置；准备完毕恢复 HP／MP 至 100 并保存，教皇战失败可直接重试此处 |
| 教皇败亡后完成逃离、尾声完成 | 逃离过场结束再存；尾声完成另记通关，cg1→cg2 的过场间不存半段 |

**避免误覆盖：** 回档只载入所选快照，不自动改写手动槽，也不在“刚读入”时立即产生自动存档。玩家继续推进到下一个自动保存节点后才写新记录；读入中的旧保存请求不得覆盖新进度。手动槽被再次覆盖和自动历史轮换淘汰后，其更早版本不无限保留，界面明确显示当前可回到的记录。

**离开与失败反馈：** 暂停菜单同时提供继续、存档、读档、设置、返回标题。返回标题前若有未保存进度，提示先手动保存或确认离开；不依赖关闭浏览器时的最后一次网络请求来保证存档。自动存档图标区分“保存中／已保存／失败”，断网或写入失败时继续保留内存中的游戏。无存档、记录不可读或版本不兼容时说明原因，不默默开始新游戏。

### 4.5 设置与两套控制预设

标题页与暂停菜单均可打开同一套设置，首版只支持**键鼠模式**和**纯键盘模式**，暂不制作手柄输入、手柄按键图标或震动。首次默认键鼠模式，玩家可手动切换；两套预设分别保存自己的改键结果，点击菜单不会自动切走纯键盘模式。纯键盘预设只接受键盘绑定；键鼠预设允许键盘和鼠标按键。

| 动作 | 键鼠模式默认 | 纯键盘模式默认 |
| --- | --- | --- |
| 移动 | WASD | WASD |
| 瞄准／朝向 | 鼠标指向场景位置 | 方向键指定瞄准方向；未输入时保留上次朝向 |
| 近战普攻 | 鼠标左键 | J |
| 深海之力 | 鼠标右键 | K |
| 援助槽 1／2 | Q／E | Q／E |
| 交互／调查 | F | F |
| 切换锁定目标 | Tab | Tab |
| 暂停／打开菜单 | Esc | Esc |
| 补全文字／下一句 | 左键点击文本框、Enter 或空格 | Enter 或空格 |
| 隐藏／恢复对话框或 CG 文本 | H | H |
| 查看本段对白记录 | R | R |

纯键盘模式通过方向键、Enter 与 Esc 完成菜单导航、存读档、设置、援助配置和对白，不要求点击才能继续。方向键在游戏中负责瞄准，在菜单中负责导航，按当前上下文分派。纯键盘瞄准优先使用当前方向；Tab 在有效射程内的敌人间循环锁定，方向键重新指定方向时解除锁定，无目标时仍可沿上次朝向攻击。键鼠模式向光标方向施放；人物动作按主要轴选取四方向，水球飞行采用实际瞄准向量。普攻范围跟随瞄准方向，移动输入不强行覆盖已经指定的瞄准。

| 设置类别 | 可调整内容 | 生效与保存方式 |
| --- | --- | --- |
| **声音** | 总音量、背景音乐、音效分别 0～100%，总静音 | 即时预览；首次声音在用户开始或确认交互后启用，尊重浏览器播放限制 |
| **操作** | 选择预设、逐动作改键或鼠标键、恢复当前预设默认值 | 两套配置独立保存；已修改时显示“自定义”，切回另一套不会丢失 |
| **阅读** | 逐字速度、即时显示全文、正文大小 | 对后续对白即时生效，历史记录同样保持可读 |
| **演出** | 屏幕震动开关、减少强闪光 | 保留清楚的攻击范围与伤害提示，不改变战斗数值 |
| **存档** | 自动存档开关，默认开启 | 关闭时明确提示需要手动保存；已有手动／自动记录仍可读取，新冒险的初始记录仍保留 |

改键采用“选择动作 → 录入新键 → 检查 → 应用”的流程。同一上下文内发生冲突时，明确展示冲突动作，让玩家选择交换或取消，不静默抢占；游戏、对话、菜单上下文可合理复用同一按键。菜单导航、确认与返回也列入可改动作，Esc 额外保留为菜单后退兜底。必需动作不能全部解除绑定，浏览器保留组合键不作为可用绑定，页面只在游戏区域处理鼠标右键与 Tab 等输入。设置页保留可点击的恢复默认和返回操作，菜单后退始终有 Esc 兜底，防止改键后无法操作。

设置按当前浏览器保存，不随剧情回档倒退，也不写进每个游戏存档；刷新与重新进入后恢复最近已应用配置。设置损坏时恢复默认并提示。切换模式、结束改键、退出菜单或窗口失焦时清除按住状态，窗口失焦自动暂停，避免恢复后持续移动或误放技能。界面提示与教学按当前绑定显示，不把 J、K 等默认键写死在对白中。

### 4.6 简单与困难

开始新冒险时选择**简单**或**困难**，默认简单。首版为简化存档和遭遇状态，难度按本次冒险固定；暂停设置中显示当前难度，要体验另一模式则新建冒险，已有冒险与记录保留。难度属于进度数据，读取任意旧档恢复其难度，不被浏览器声音或键位设置覆盖。

| 项目 | 简单 | 困难 |
| --- | --- | --- |
| 大肥鱼基础 HP 上限／初始值 | 100／100（探索获得【饱满灵谷】可累加提升上限） | 100／100（探索获得【饱满灵谷】可累加提升上限） |
| 大肥鱼基础 MP 上限／初始值 | 100／100（探索获得【深海润珠】可累加提升上限） | 100／100（探索获得【深海润珠】可累加提升上限） |
| 探索成长道具效果 | 提升普攻（鲸纹硬鳞）、提升水球（纯净潮汐核心）正常生效 | 相同提升效果 |
| 敌方最大 HP／初始 HP | 基准值 H | 2H |
| 敌方造成的伤害 | 基准值 D | 2D |
| 入队伙伴的技能效果 | 同一套基准值 | 与简单相同 |
| 独立护盾／结界耐久 | 同一套基准值 | 与简单相同 |
| 其他规则 | 基准流程与参数 | 与简单相同 |

**只修改敌方血量和伤害。** 两模式的敌人数目、移动速度、攻击频率、AI、弹速、预警、控制时长、技能 CD、MP 消耗与回复、地图、剧情和结局一致；不以“困难”为由新增招式或削减补给。敌方直接伤害与持续伤害的每次伤害量都先乘难度系数，再按同一减伤规则结算，不能在生成和命中时重复翻倍。例如简单敌人 HP 50、一次造成 10 伤害，困难对应 HP 100、伤害 20。

倍率只用于敌态实例，覆盖杂兵、事件战 GLM、试炼 GPT 和 D 教皇；变为支援后的角色不继承敌态倍率。Claude 切磋不扣本体 HP，原本为 0 的伤害在困难仍为 0；其防御结界与 GPT 的龙鳞护盾都是独立耐久，不因敌方 HP 翻倍而额外翻倍。GLM 的 30% 投降阈值与教皇的 50% 转阶段阈值按各自模式的最大 HP 计算，GPT 仍只需破盾后造成一次本体伤害。剧情强制受伤、治疗与逃离演出不参加敌方伤害倍率。

## 6. 前后端课程边界（简要规划）

按 [React 前端课程规范](../../course-skills/react-course-frontend/SKILL.md) 与 [Scala 后端课程规范](../../course-skills/scala-course-homework/SKILL.md) 实施：前端采用 **React＋TypeScript＋Tailwind**；后端采用 **Scala 3 与课程 API／IO／Table 组织方式**；数据库默认 **PostgreSQL**。游戏绘制采用 Canvas 2D；服务边界、关卡设计与实施阶段见 [开发 Plan](../docs/development-plan.md)，接口字段和数据库 schema 按该计划细化。

**前端负责**输入与改键、绘制、即时战斗、对话、设置及存读档界面；**后端负责**冒险与存档记录查询、快照校验和持久化。战斗逐帧计算留在浏览器，手动／自动保存的安全快照提交后端，不把每次移动和攻击变成网络请求。

### 拟定页面与服务

| 页面目录／URL | 用途与主要区域 | 依赖服务 |
| --- | --- | --- |
| `frontend/src/pages/StartPage/` ／ `/` | 标题、开始新游戏与难度选择、继续游戏、读取存档与设置入口 | `PlayerService`、`AdventureService` |
| `frontend/src/pages/GamePage/` ／ `/game` | 游戏场景、HP/MP 与援助栏、对话、暂停、手动保存／读取、失败重试、设置；结局在本页呈现 | `AdventureService` |

首版设两个逻辑业务服务：`PlayerService` 负责匿名玩家、访问令牌与可信身份，拥有 `PlayerTable`、`PlayerSessionTable`，公开 `CreateAnonymousPlayerMessage`，内部提供 `ResolvePlayerMessage`；`AdventureService` 负责多次冒险、存档与请求去重，拥有 `AdventureTable`、`GameSaveTable`、`ProgressOperationTable`，公开 `StartAdventureMessage`、`ListSavesMessage`、`LoadAdventureMessage`、`SaveProgressMessage`。玩家进度版本与继续指针由玩家表维护，冒险消息通过公开 Table 方法在同一事务中更新。`services/system/` 单独承担数据库连接、事务与路由基础设施，不计为第三个业务服务。

角色、地图、关卡、敌人分别建立明确的数据模型和版本化内容模块，不按实体名各拆微服务；即时战斗留在浏览器。课程项目按逻辑边界组织，同进程部署即可。后端校验访问归属、难度、HP／MP 边界、安全位置与剧情／伙伴一致性，拒绝回档后的旧请求；新写入成功前保留原记录，读入后不立即覆盖来源记录。

调用关系为：**开始页／游戏页的存读档区域 → `src/apis/AdventureService/` 下同名请求类 → 后端消息的 `plan` → 快照校验／公开 Table 方法 → PostgreSQL**。公共传输放 `src/api/`；游戏页专用组件、状态与纯函数就近组织，Zustand 封装需要共享的核心状态，展示数据由纯函数推导。开始页和游戏页共用的设置、存档列表按实际复用需要组织，不新建无必要的业务服务。

### 存档与设置的边界

首版采用匿名玩家访问令牌，由后端签发，浏览器保存；后端校验后定位该玩家拥有的冒险与存档。新冒险创建成功后才切换当前冒险，原来的冒险及其存档保留在列表中。暂不制作注册、登录或多端同步界面。

难度、剧情进度、资源和冷却随所选快照恢复；声音、改键、阅读与演出设置保存在当前浏览器，独立于剧情存档。存读档具体体验见第 4.4 节，两套控制方案和设置见第 4.5 节。网络失败时，只有收到后端成功响应才显示“已保存”，失败不把未写入数据库的进度伪装为有效存档。

AI 用于协助本项目的策划、素材整理与开发。首版主线与战斗采用确定的内容，不依赖实时模型生成；课程材料并未要求每份作业调用云服务。如后续确需模型能力，再按 [TokenHub 技能](../../course-skills/tencent-tokenhub/SKILL.md) 在服务端接入。

## 7. 对话演出与美术素材

### 7.1 视觉小说式对话

剧情采用“**场景背景＋人物立绘＋底部文本框**”的固定布局。普通谈话以当前像素地图的静止画面为背景，稍微压暗；人物立绘保留原插画风，显示在文本框上方；底部文本框包含说话者名字、正文和继续提示。两人对话时立绘分别放在左右，当前说话者正常显示，另一人适度压暗；多人轮流说话时替换当前立绘，首版同屏最多两人。

- **构图：** 文本框占画面底部约四分之一，正文每次约 2～3 行；立绘按比例缩放、脚部或裙摆可被文本框遮挡，脸部与关键饰物完整可见，不拉伸图片。角色原始立绘使用 `portraits/default.png`，初期依靠明暗和轻微位移区分语气，表情差分后续补充。
- **阅读操作：** 文字逐字出现；默认点击文本框、按空格或 Enter，第一次补全当前句，文字显示完后再推进下一句；改键后使用当前绑定。提供关闭打字效果和本段对话回看；首版不制作分支选项、好感度和语音配音。
- **暂停与恢复：** 进入剧情时暂停移动、敌人、投射物、伤害、MP 回复和技能 CD。对话关闭后再恢复；确认按键只推进对白，不触发一次额外攻击。多数对白放在遭遇前或结束后；剧本要求的战中呼唤按预设阶段短暂停战后展示，不额外制作实时边打边读系统。
- **提示与重播：** 当前任务在对白结束后更新。剧情中的调查与解锁事件只结算一次；检查点重载允许重播未保存的段落，不重复发放伙伴、重开已经解除的封印。主线对白可逐句快速推进，不默认自动跳过。

关键对白节点为：序章分离、Qwen 指路、GLM 被抓与归还行囊、Gemini 获救、GPT 提出和认可试炼、圣殿内庭重逢（劝说与切磋）、Claude 决意同行、教皇战前对峙、教堂坍塌逃亡、cg1/cg2 演出以及战后尾声。每段围绕一个目标展开，避免一次放入大段设定说明。

**对白直接使用剧本：** 内庭重逢按场景 5-2 → 战斗 5-B → 场景 5-3 的顺序执行，不再另列可能与完整版不一致的对白草案。Claude 结界破碎后的拥抱先用像素角色靠近、花瓣与立绘表现，天空背景 CG 留到战后。

Claude 决意同行后，D 教皇现身；对白收束后开放终战准备与检查点，再开始 5-C。教会执事、审判长可使用姓名框配通用像素形象或剪影，不强求额外高规格立绘。剧本的表情、抱肩、擦泪等先用单张立绘的明暗、位移和像素过场概括，不把每个括号动作都视为必做动画差分。

### 7.3 像素风范围与四方向规范

除人物对话立绘和特殊 CG 外，**地图地块、建筑、场景角色、敌人、道具图标、战斗与技能特效全部采用统一的像素风**。界面采用简洁的像素边框和小图标，中文正文保留清晰可读的字体，不强行把汉字压成低分辨率像素。

- **视角与方向：** 场景采用俯视／轻俯视的正交 RPG 视角，角色具备朝下、朝上、朝左、朝右四个方向；斜向移动按最近主要轴选一个方向，停止时保留上一次朝向，暂不制作八方向。
- **比例与画风：** 小头身 Q 版，约 2.5 头身；统一深色轮廓、有限色阶和清晰像素块。像素角色保留发色、耳角、尾巴、服装主色与代表饰物，简化立绘繁复花纹。显示时使用最近邻采样，避免模糊缩放；像素角色的脚底作为场景定位点，碰撞只覆盖脚边小范围，头发、裙摆和龙翼不直接增加碰撞体积。
- **站立素材：** DeepSeek、Claude、GPT、GLM、Qwen、Gemini 各有一张 `idle-directions.png`。图集按 **2×2** 排列，左上朝下、右上朝上、左下朝左、右下朝右，每格是一个站立方向。各角色独立目录，不把所有人的素材堆在 `Character/` 根目录；一张图集集中同角色的四方向，便于后续加载。
- **使用边界：** 站立图用于样貌、朝向与摆位；本轮新增的动作图集与特效单独记录在 `animation-manifest.json`，不能用站立图替代动作帧。生成后的尺寸、分格、播放顺序与定位按配套清单记录；不把生成图的高分辨率画布当成游戏中的逻辑尺寸，接入时统一角色在世界中的显示高度与视觉基线。

| 角色／对象 | 当前可用 | 首版实现前需补齐 |
| --- | --- | --- |
| **大肥鱼** | 原立绘、四方向站立图、四方向行走／摆尾／施法图集、水球飞行与命中特效 | 动画在引擎中的切帧与脚底校准；受伤闪烁与倒下表现 |
| **GLM** | 原立绘、四方向站立图、禁书之缚施法图集与独立束缚特效 | 港镇四方向移动、符文闪避与书页炸弹事件战表现；施法时序同步 |
| **GPT** | 原立绘、四方向站立图、群星之力施法图集与独立星落特效 | 独立龙鳞护盾条／破碎特效、冰极龙息／落击动作；破穹顶过场复用星辉，仍沿用龙娘形态 |
| **Claude** | 原立绘、四方向站立图、向日葵结界施法图集与独立结界特效 | 切磋用法杖、缓速花阵和可破护盾表现；援助结界分层与时序，现有支援图集不等于已完成切磋素材 |

| **Kimi、Grok** | 保留原立绘与角色设定 | 扩展角色，本轮不生成像素图、不加入首版加载清单 |

本轮大肥鱼的行走、摆尾、施法各采用 **3 列×4 行**：行依次朝下、上、左、右，列依次为同一动作的三个阶段。行走按“站姿 → 迈步 A → 站姿 → 迈步 B”循环；摆尾与施法按“预备 → 出手 → 收势”单次播放。伤害与 MP／CD 结算由游戏状态控制，不能因重复显示同一帧而重复触发。

GLM、GPT、Claude 的支援施法各采用 **2×2 的四阶段图集**，按左上、右上、左下、右下播放；这些是同一正面施法动作的时间帧，不是四方向。支援固定召唤朝向即可，不额外扩成多角色四方向战斗系统。各自的区域特效独立存于 `effects/`，播放位置由目标区域或玩家位置决定，不随施法角色图片一同硬编码。

水球特效为 **4 列×2 行**：上行四帧是朝右飞行的弹体，可按实际瞄准向量旋转；下行四帧是命中水花，单次播放。GLM 束缚、GPT 星落、Claude 结界各有 **2×2 四阶段**特效。持续型束缚与结界在成型阶段保持到状态结束，再播放消散；状态实际是否生效由战斗系统判定，动画长短不改变技能 CD。

### 7.4 素材目录与维护

`Character/setting.md` 保留统一角色设定，`Character/README.md` 提供素材索引和当前完成状态。目录如下（已生成素材与后续计划分开记录）：

```text
material/
├── script.md                       # 当前对白、场景与演出依据
├── Character/
│   ├── README.md
│   ├── setting.md
│   ├── manifest.json                 # 当前六名角色的素材与四方向分格信息
│   ├── generation-prompts.md         # 站立素材的生成记录
│   ├── animation-manifest.json       # 动作／技能图集与播放定义
│   ├── animation-preview.html        # 本地播放与逐帧检查
│   ├── animation-generation-prompts.md # 动作／技能生成记录
│   ├── deepseek/                     # claude、gpt、glm、qwen、gemini 同样组织
│   │   ├── portraits/default.png     # 原始立绘，保留原图
│   │   ├── sprites/                  # idle-directions、walk、melee-tail、cast-water
│   │   └── effects/water.png         # 水球飞行与命中；支援角色同样单列 effects/
│   ├── kimi/portraits/default.png    # 扩展预留，仅保留立绘
│   └── grok/portraits/default.png
└── cg/
    ├── README.md                     # 使用位置与版本说明
    ├── cg1.png                       # 结尾第一幕：二人相拥
    ├── cg2.png                       # 结尾第二幕：GPT 见证
    └── reference.png                 # 制作参考，不进游戏
```

原始立绘、现有 CG 和本轮像素图分别记录来源，像素改编不覆盖原图。后续完善动作时，在对应角色的 `sprites/` 或 `effects/` 下新增图集并更新清单；本轮资产不覆盖既有立绘和站立图。素材进入应用时只选择实际使用的文件，不把参考图和预留角色全部打包进游戏。

音乐围绕出发、旅途、试炼与重逢切换；攻击、受伤、施法失败和技能就绪给出简洁的声音或视觉反馈。这是非官方同人课程项目，展示时注明素材来源，公开发布时按实际许可使用。

整个 `hw_m` 由独立 Git 仓库管理，企划、角色材料和后续前后端代码统一纳入版本历史。课程技能由相邻 `course-skills` 仓库维护，通过文档链接引用。

## 8. 首版验收目标

1. 玩家能从标题页开始，在序章看到 Claude 被带走与大肥鱼反抗失败，随后按 Qwen 指引前往港镇。
2. 能完成 GLM 偷窃事件、归还物品与渡海，帮助 Gemini 后获得北境线索，再通过“击破护盾并伤到 GPT”的试炼。
3. 大肥鱼可用近战普攻与唯一的远程技能；MP 不足和 CD 未结束均能正确阻止施法。
4. GLM、GPT、Claude 各仅有一个带独立 CD 的援助技能，解锁顺序正确；能选择援助并在终战实际使用 Claude 的结界。
5. 能与 GPT 突破教会守卫，在圣殿内庭通过嘴炮与切磋解开 Claude 心结，再和她共同击败 D 教皇，经历大教堂坍塌逃脱后顺次进入 cg1、cg2，看到两人自由生活的结局。
6. 手动与自动进度通过 Scala 后端写入 PostgreSQL；能区分 5 个手动槽与最近 3 条自动记录，刷新后继续游戏，也能选择旧记录回档，恢复该快照的任务、伙伴、位置、资源与冷却。
7. 普通倒下、GPT 试炼失败、存档加载或保存失败均有明确反馈，并能重试；两次剧情战败或重伤不造成流程卡死。
8. 剧情以人物立绘＋底部文本框呈现；阅读时战斗与计时暂停，推进对白不会误触攻击，结束后正确恢复游戏。
9. 地图和场景角色使用统一像素风，四方向正确切换；结尾顺次播放 cg1 与 cg2，CG 比例完整，能隐藏文本框查看画面。
10. 手动覆盖与放弃未保存进度有明确确认；存读档失败保留原记录与当前游戏，回档后不会被先前保存请求或立即自动存档覆盖。
11. 键鼠、纯键盘两套预设均能完成移动、瞄准、战斗、对话、存读档与菜单操作；可分别改键，冲突有处理，提示跟随新绑定，不显示手柄入口。
12. 音量、静音、阅读和演出设置可调，刷新后保留；剧情回档不恢复旧设置，窗口失焦暂停且不残留按键状态。
13. 大肥鱼行走帧有交替迈步，摆尾有预备／出手／收势；三名支援的施法动作与区域特效分离，动画播放不会重复结算伤害或扣除资源。
14. 大肥鱼在两模式中 HP／MP 基础上限均为 100，探索成长效果一致；普通敌人与敌态 Boss 的困难最大 HP、伤害恰为简单的 2 倍，其余参数一致，支援伤害与独立护盾不加倍。
15. GLM 按相对 30% HP 阈值投降，GPT 破盾并受一次本体伤害即通过，Claude 切磋只破盾且不杀伤本体，教皇按相对 50% HP 转阶段；困难模式不改变这些条件。
16. 试炼成功后的剧情 0 HP 不触发失败或生成濒死存档；回档恢复所属难度与事件阶段，Claude 切磋后的终战重试不必重打回廊和切磋。
