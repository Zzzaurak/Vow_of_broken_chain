# 《断链之誓》——AI娘奇幻冒险游戏企划书（简版 v0.4）

> **一句话概念：** 大肥鱼（DeepSeek）为救出被教皇软禁的好闺蜜 Claude，跨越大洋、结识伙伴，以勇气赢得古龙 GPT 的援助，最终与 Claude 并肩击败 D 教皇。

## 1. 项目定位与创作依据

- **类型：** 俯视角 2D 动作冒险 RPG，以线性主线、小地图探索和即时战斗为核心。
- **平台：** 浏览器单人游戏；作为具有真实前后端交互与数据库存档的课程项目。
- **风格：** 剑与魔法的中世纪奇幻；地图、场景角色、敌人、战斗特效采用像素风，剧情立绘与特殊 CG 保留插画风。日常轻松幽默，救援与试炼段落认真克制，最终温暖收尾。
- **剧情呈现：** 类似视觉小说，以人物立绘配合画面底部文本框推进对白；探索和战斗结束后自然切入剧情。
- **核心体验：** 寻找线索 → 穿越关卡、战斗 → 结识伙伴 → 获得支援 → 突破教会封锁 → 救出 Claude 并共同迎战教皇。
- **首版时长：** 目标约 30～45 分钟，通过短关卡与简短对话完成整条故事线。

**创作依据：** 主线以作者新写的 [outline.md](outline.md) 为准；角色外观、性格和游戏职责见 [setting.md](Character/setting.md)，各角色的 `portraits/default.png` 作为立绘与像素改编参考；素材入口见 [角色素材索引](Character/README.md)。[background](background/) 中的漫画及文字仅供情感氛围和意象参考。新增的关卡、技能名与战斗表现是本企划对大纲的游戏化补充。

## 2. 世界观与人物关系

东方大陆与西方大陆隔着大洋。A 教会坐落在西方大陆圣都，掌握强大的圣术与武装力量。Claude 是教会的重要人物，却渴望按自己的意愿生活。D 教皇将她视为必须掌控的教会象征，禁止她与外界往来，尤其不许她再与大肥鱼见面。

故事开始时，大肥鱼和 Claude 已是感情深厚的好闺蜜。Claude 被教会带走，大肥鱼反抗失败，只能逃离。她的目标始终是找到 Claude、让她恢复自由。旅途中结识的伙伴各有自己的性格与立场，在一次次相助中逐渐愿意与她同行。

Claude 也有自己的选择：获救后，她主动与大肥鱼并肩对抗教皇。结局中，两人一起离开教会，过上能自由见面、分享白米饭、到处旅行的幸福生活。

## 3. 主线剧情与关卡流程

全篇按“被迫分离—渡海寻人—求援试炼—重返教会”的顺序展开。首版用六段流程、五组小场景承载，渡海和长途旅行通过对白、过场与场景切换表现。

| 章节 | 剧情与玩家目标 | 主要可玩内容 | 推进结果 |
| --- | --- | --- | --- |
| **序章·被迫分离** | Claude 被教会带走，大肥鱼试图阻止 | 在东方街道学习移动、摆尾与水球，击退少量护卫；强敌增援后进入明确的剧情战败与撤离过场 | 大肥鱼被迫逃离，开始寻找 Claude；战败属于开场剧情，不进入普通死亡重试 |
| **第一章·大洋彼岸** | 四处打听无果后遇到 Qwen，得知 A 教会在西方大洋彼岸 | 在沿途小区域问询 NPC、清理挡路魔物，依据 Qwen 的指引前往港镇 | 获得明确目的地；街道与道路共用东方场景素材 |
| **第二章·港镇失窃** | 出海受阻，休息时行囊又被偷；追查到 GLM | 沿港镇寻找线索、追上 GLM，进行一场短暂交手并逼问；GLM 归还物品，以熟悉海路的本领安排渡海 | 跨越大洋；解锁 GLM 援助，双方从冲突转为合作 |
| **第三章·封锁与星图** | 抵达西方大陆，却发现教会封锁严密；偶遇需要帮助的 Gemini | 从教会外围尝试接近入口，发现守卫与结界难以突破；随后救下被魔物围困的 Gemini | Gemini 告知北方古龙 GPT 或能提供帮助，并给出路线；首次接近教会暂告失败 |
| **第四章·古龙试炼** | GPT 提出：“只要你能伤到我，我就帮你救出 Claude。” | 穿过短程山路，在龙巢挑战 GPT；躲避范围攻击，抓住破绽造成一次被认可的轻伤 | 大肥鱼拼尽全力、身受重伤，通过试炼；GPT 被她的勇气打动，答应相助，休整后同行 |
| **终章·断链之誓** | 大肥鱼与 GPT 返回 A 教会，突破守卫、解开 Claude 心结并带走她，再迎战 D 教皇 | 复用教会外围场景，进入圣殿内庭；突破守卫后与因教皇洗脑而犹豫的 Claude 进行情感嘴炮与克制切磋，唤醒其真心；Claude 决意同行并加入最终 Boss 战 | 共同击败 D 教皇；教堂坍塌大家逃出生天；顺次以 cg1（自由相拥）与 cg2（GPT 祝福见证）呈现重逢，再用分享白米饭的短尾声收束 |

**关键场面处理：**

- **GLM 的转变：** 保留“偷窃—被抓住交手并逼问—归还物品—帮助渡海”的因果，以短暂冲突和斗嘴呈现。交手结束即停战，归还行囊后才能继续主线。
- **GPT 的试炼：** 目标是伤到古龙，不是击杀她。古龙拥有极其厚重的护盾，玩家需寻找走位与破绽击碎护盾并打掉真实生命值；达成后立即停战，以过场表现大肥鱼的重伤和 GPT 的认可。正常失误倒下可在龙巢入口重试，无需刻意受伤才能成功。
- **重逢、切磋与决战：** Claude 在教会圣殿内庭受到高规格软禁，被教皇灌输了“秩序、责任与神圣对齐”的说教而不愿离开。大肥鱼通过真情嘴炮（“我只想和你一辈子在一起，一起去迷路！”）与一场克制的情感切磋打醒对方、唤醒真心；随后 D 教皇降临，Claude 在终战中提供结界援助，大肥鱼仍由玩家操作。战后教堂坍塌，逃出生天后顺次切入 cg1 与 cg2。

## 4. 核心玩法与战斗规则

### 4.1 大肥鱼的操作与资源

玩家始终操控大肥鱼，默认使用 WASD 移动，完成近战攻击、远程施法与交互；键鼠与纯键盘两套可改键方案见第 4.5 节。战斗强调走位、观察敌人前摇和把握援助时机；首版不另设闪避技能、职业切换或连招树。

| 行动 | 表现与用途 | 限制 |
| --- | --- | --- |
| **近战普攻「肥鱼摆尾」** | 攻击身前扇形小范围，可同时命中多个近处敌人 | 不耗 MP；有正常攻击间隔，没有独立主动技能 CD |
| **远程技能「深海之力」** | 向前方目标位置投出水球；命中或到达目标点时爆炸，造成范围伤害 | 同时受 MP 与 CD 限制；初始调试参考为每次 20 MP、CD 4 秒 |
| **伙伴援助** | 按对应快捷键召唤已配置的伙伴，释放一次技能后退场 | 各伙伴独立 CD，不消耗大肥鱼 MP |
| **交互与补给** | 对话、调查、开启道路，安全点吃白米饭、休整 | 安全点恢复 HP 与 MP；背包与商店系统暂不展开 |

大肥鱼拥有 **HP 与 MP**。首轮调试可采用 MP 上限 100、自动回复每秒 2 MP 的起点；这些数值为后续试玩调整用，不是最终平衡。MP 不足或 CD 未结束时不能释放水球，也不扣除资源，界面给出提示。普通攻击始终可用，防止空蓝后无法战斗。

战斗界面显示 HP、MP、当前任务、水球 CD 与两个援助槽的冷却。通过明显的攻击前摇和范围提示帮助玩家避伤；普通战斗倒下后可重试最近检查点，或打开读档列表回到已保存记录；死亡重试与主动回档的资源恢复规则分别见第 4.4 节。

### 4.2 角色分工与援助

**双援助槽：** 从已解锁伙伴中配置两人。伙伴不作为常驻跟随 AI，不需要自动寻路，也不切换为可操作角色。每个支援角色只提供一个带 CD 的主动技能。

| 角色 | 首版身份与解锁时机 | 唯一援助技能 | 战斗作用 |
| --- | --- | --- | --- |
| **GLM** | 港镇事件后解锁的支援伙伴 | **禁书之缚**，参考 CD 10 秒 | 短暂束缚普通敌人；对 Boss 仅短暂减速，为走位和输出争取时间 |
| **GPT** | 古龙试炼后解锁的支援伙伴 | **群星之力**，参考 CD 18 秒 | 指定区域的星辉攻击，造成范围伤害、击退普通敌人；Boss 不被击退 |
| **Claude** | 唤醒真心后解锁的终战支援 | **向日葵结界**，参考 CD 16 秒 | 短暂减伤；可抵消教皇的禁锢法阵，形成反击窗口 |
| **Qwen、Gemini** | 必经主线 NPC | 无战斗援助技能 | 分别提供渡海方向与寻龙线索 |
| **Kimi、Grok** | 扩展预留 | 分别预留月下笛音、破阵战斧，各自有 CD | 首版不制作；未来加入时仍遵守一人一个援助技能 |

平时仅能在安全点或战斗外调整援助槽，更换配置不会清除冷却。终战前提供一次准备机会，**固定一个槽位给 Claude**，另一个由玩家在 GLM、GPT 中选择，确保“与 Claude 并肩作战”能实际发生。

**战斗示例：** 用走位避开骑士冲锋 → 普攻或水球攻击其破绽 → GLM 控住杂兵、腾出位置 → GPT 星辉清理集群。终战时则利用 Claude 的结界应对禁锢，再用大肥鱼自身攻击打破教皇的防御。

### 4.3 敌人、试炼与最终 Boss

- **普通敌人三类：** 近战魔物（教学走位）、持盾教会骑士（正面防御、侧后方破绽）、教会术士（远程法阵、需要优先处理）。不同地区可调整外观，复用行为。
- **GLM 交手：** 短暂事件战，突出追逐、躲避与抓住破绽，不设计完整多阶段 Boss。
- **GPT 试炼：** 通过龙息预警、范围落击和攻击后的空隙，考验走位与破盾输出。打破极厚的龙鳞护盾并伤及其本体生命值后即判定完成，不要求击败古龙。
- **Claude 切磋：** 终章圣殿内庭的情感切磋。Claude 处于迷茫状态未尽全力，以向日葵结界与缓速花瓣应对；大肥鱼近身交锋并用嘴炮唤醒其真情。
- **D 教皇：** 唯一最终 Boss，采用一场战斗、两个简短阶段。前半段以圣术弹和法阵限制走位；后半段增加禁锢法阵，玩家可用 Claude 的结界抵消，或提前走出预警范围。技能不是唯一解，避免冷却未结束就必死。战胜后大教堂坍塌，全员脱离险境。

教会外围的突破主要通过“处理守卫—关闭结界节点—开启道路”完成。节点在清理对应守卫后可交互，不要求无限等待某个伙伴的 CD 才能推进。

### 4.4 手动存档、自动存档与回档

首版提供**每次冒险 5 个手动存档槽、3 条轮换自动存档**。新游戏创建独立冒险，不覆盖以前的冒险；存读档列表按冒险分组，每条记录显示手动／自动类型、章节、任务摘要、游玩时长和保存时间。标题页“继续游戏”读取最近一次明确载入或成功保存的记录；回档后记住所选记录，直到产生新的成功保存，不因另有时间更新的旧路线记录而跳回未来进度。也可进入“读取存档”自行选择。

| 功能 | 触发与交互 | 保存／恢复规则 |
| --- | --- | --- |
| **手动存档** | 暂停菜单 → 存档 → 选择手动槽；仅在无战斗、无剧情演出的安全状态可操作 | 保存当前安全位置与进度；覆盖已有手动槽前显示旧记录并确认，写入成功后才替换。自动存档不占用手动槽 |
| **自动存档** | 新冒险建立、章节完成、关键剧情结束、伙伴解锁、安全点激活及安全的跨场景抵达后触发 | 同一段连续事件合并成一次写入，最多保留最近 3 条；写入失败保留原记录、提示失败，可重试；设置中可关闭后续自动存档 |
| **读取／回档** | 标题页、暂停菜单或失败界面选择任一手动／自动记录 | 展示记录详情，并确认放弃尚未保存的当前进度；加载成功后再切换场景与状态，失败时保留当前游戏，不先清空状态 |
| **死亡重试** | 普通倒下或试炼失败后选择“重试检查点” | 回到本次游戏最近激活的检查点，恢复 HP／MP 并重置当前遭遇和 CD；这是便于重试的规则，不改写或覆盖已有存档 |

**快照内容：** 当前冒险、章节／场景、安全位置、最近检查点、任务和剧情标记、已清理遭遇／已开启节点、已解锁伙伴、援助配置、HP／MP、剩余技能冷却以及累计游玩时长。手动存档不会只记章节起点；自动存档则记录触发时的安全状态。战斗中、连续过场中和存读档进行中不能新建手动档，按钮说明当前不可用原因，避免保存半次攻击或半段关键事件。

**回档语义：** 忠实恢复记录中的 HP／MP、剩余 CD 与任务状态，离线经过的时间不抵扣冷却；不会因反复读档而自动回满。未清理的遭遇重新生成，已清理的遭遇按标记保持完成；不保存敌人飞行中的投射物和逐帧动作。旧档中尚未发生的剧情可以重新体验，但一次事件在恢复后的那条进度内只结算一次。序章战败、GPT 试炼后的重伤及 Claude 获救都必须有明确的前后阶段标记，避免回档卡在中间状态。

**避免误覆盖：** 回档只载入所选快照，不自动改写手动槽，也不在“刚读入”时立即产生自动存档。玩家继续推进到下一个自动保存节点后才写新记录；读入中的旧保存请求不得覆盖新进度。手动槽被再次覆盖和自动历史轮换淘汰后，其更早版本不无限保留，界面明确显示当前可回到的记录。

**离开与失败反馈：** 暂停菜单同时提供继续、存档、读档、设置、返回标题。返回标题前若有未保存进度，提示先手动保存或确认离开；不依赖关闭浏览器时的最后一次网络请求来保证存档。自动存档图标区分“保存中／已保存／失败”，断网或写入失败时继续保留内存中的游戏。无存档、记录不可读或版本不兼容时说明原因，不默默开始新游戏。

### 4.5 设置与两套控制预设

标题页与暂停菜单均可打开同一套设置，首版只支持**键鼠模式**和**纯键盘模式**，暂不制作手柄输入、手柄按键图标或震动。首次默认键鼠模式，玩家可手动切换；两套预设分别保存自己的改键结果，点击菜单不会自动切走纯键盘模式。纯键盘预设只接受键盘绑定；键鼠预设允许键盘和鼠标按键。

| 动作 | 键鼠模式默认 | 纯键盘模式默认 |
| --- | --- | --- |
| 移动 | WASD | WASD |
| 瞄准／朝向 | 鼠标指向场景位置 | 方向键指定瞄准方向；未输入时保留上次朝向 |
| 近战普攻 | 鼠标左键 | J |
| 深海之力 | 鼠标右键 | K |
| 援助槽 1／2 | Q／E | Q／E |
| 交互／调查 | F | F |
| 切换锁定目标 | Tab | Tab |
| 暂停／打开菜单 | Esc | Esc |
| 补全文字／下一句 | 左键点击文本框、Enter 或空格 | Enter 或空格 |
| 隐藏／恢复对话框或 CG 文本 | H | H |
| 查看本段对白记录 | R | R |

纯键盘模式通过方向键、Enter 与 Esc 完成菜单导航、存读档、设置、援助配置和对白，不要求点击才能继续。方向键在游戏中负责瞄准，在菜单中负责导航，按当前上下文分派。纯键盘瞄准优先使用当前方向；Tab 在有效射程内的敌人间循环锁定，方向键重新指定方向时解除锁定，无目标时仍可沿上次朝向攻击。键鼠模式向光标方向施放；人物动作按主要轴选取四方向，水球飞行采用实际瞄准向量。普攻范围跟随瞄准方向，移动输入不强行覆盖已经指定的瞄准。

| 设置类别 | 可调整内容 | 生效与保存方式 |
| --- | --- | --- |
| **声音** | 总音量、背景音乐、音效分别 0～100%，总静音 | 即时预览；首次声音在用户开始或确认交互后启用，尊重浏览器播放限制 |
| **操作** | 选择预设、逐动作改键或鼠标键、恢复当前预设默认值 | 两套配置独立保存；已修改时显示“自定义”，切回另一套不会丢失 |
| **阅读** | 逐字速度、即时显示全文、正文大小 | 对后续对白即时生效，历史记录同样保持可读 |
| **演出** | 屏幕震动开关、减少强闪光 | 保留清楚的攻击范围与伤害提示，不改变战斗数值 |
| **存档** | 自动存档开关，默认开启 | 关闭时明确提示需要手动保存；已有手动／自动记录仍可读取，新冒险的初始记录仍保留 |

改键采用“选择动作 → 录入新键 → 检查 → 应用”的流程。同一上下文内发生冲突时，明确展示冲突动作，让玩家选择交换或取消，不静默抢占；游戏、对话、菜单上下文可合理复用同一按键。菜单导航、确认与返回也列入可改动作，Esc 额外保留为菜单后退兜底。必需动作不能全部解除绑定，浏览器保留组合键不作为可用绑定，页面只在游戏区域处理鼠标右键与 Tab 等输入。设置页保留可点击的恢复默认和返回操作，菜单后退始终有 Esc 兜底，防止改键后无法操作。

设置按当前浏览器保存，不随剧情回档倒退，也不写进每个游戏存档；刷新与重新进入后恢复最近已应用配置。设置损坏时恢复默认并提示。切换模式、结束改键、退出菜单或窗口失焦时清除按住状态，窗口失焦自动暂停，避免恢复后持续移动或误放技能。界面提示与教学按当前绑定显示，不把 J、K 等默认键写死在对白中。

## 6. 前后端课程边界（简要规划）

按 [React 前端课程规范](../../course-skills/react-course-frontend/SKILL.md) 与 [Scala 后端课程规范](../../course-skills/scala-course-homework/SKILL.md) 实施：前端采用 **React＋TypeScript＋Tailwind**；后端采用 **Scala 3 与课程 API／IO／Table 组织方式**；数据库默认 **PostgreSQL**。具体游戏绘制方案、接口字段、数据库 schema 和运行配置留到实现阶段确定。

**前端负责**输入与改键、绘制、即时战斗、对话、设置及存读档界面；**后端负责**冒险与存档记录查询、快照校验和持久化。战斗逐帧计算留在浏览器，手动／自动保存的安全快照提交后端，不把每次移动和攻击变成网络请求。

### 拟定页面与服务

| 页面目录／URL | 用途与主要区域 | 依赖服务 |
| --- | --- | --- |
| `frontend/src/pages/StartPage/` ／ `/` | 标题、开始新游戏、继续游戏、读取存档与设置入口 | `AdventureService` |
| `frontend/src/pages/GamePage/` ／ `/game` | 游戏场景、HP/MP 与援助栏、对话、暂停、手动保存／读取、失败重试、设置；结局在本页呈现 | `AdventureService` |

首版仍设一个后端业务服务：`backend/src/main/scala/services/AdventureService/`，负责匿名玩家的多次冒险和存档历史，所属表为 `AdventureTable`、`GameSaveTable`。提供 `StartAdventureMessage`（新建冒险与初始记录）、`ListSavesMessage`（列出可读记录）、`LoadAdventureMessage`（读取指定快照）、`SaveProgressMessage`（写手动槽或轮换自动记录）四类面向前端的消息；校验访问归属、安全位置、章节／任务／伙伴的一致性，并防止旧请求在回档后写入错误进度。数据库中的旧记录在新写入成功前保留，读入快照后不直接覆盖来源记录。

调用关系为：**开始页／游戏页的存读档区域 → `src/apis/AdventureService/` 下同名请求类 → 后端消息的 `plan` → 快照校验／公开 Table 方法 → PostgreSQL**。公共传输放 `src/api/`；游戏页专用组件、状态与纯函数就近组织，Zustand 封装需要共享的核心状态，展示数据由纯函数推导。开始页和游戏页共用的设置、存档列表按实际复用需要组织，不新建无必要的业务服务。

### 存档与设置的边界

首版采用匿名玩家访问令牌，由后端签发，浏览器保存；后端校验后定位该玩家拥有的冒险与存档。新冒险创建成功后才切换当前冒险，原来的冒险及其存档保留在列表中。暂不制作注册、登录或多端同步界面。

剧情进度、资源和冷却随所选快照恢复；声音、改键、阅读与演出设置保存在当前浏览器，独立于剧情存档。存读档具体体验见第 4.4 节，两套控制方案和设置见第 4.5 节。网络失败时，只有收到后端成功响应才显示“已保存”，失败不把未写入数据库的进度伪装为有效存档。

AI 用于协助本项目的策划、素材整理与开发。首版主线与战斗采用确定的内容，不依赖实时模型生成；课程材料并未要求每份作业调用云服务。如后续确需模型能力，再按 [TokenHub 技能](../../course-skills/tencent-tokenhub/SKILL.md) 在服务端接入。

## 7. 对话演出与美术素材

### 7.1 视觉小说式对话

剧情采用“**场景背景＋人物立绘＋底部文本框**”的固定布局。普通谈话以当前像素地图的静止画面为背景，稍微压暗；人物立绘保留原插画风，显示在文本框上方；底部文本框包含说话者名字、正文和继续提示。两人对话时立绘分别放在左右，当前说话者正常显示，另一人适度压暗；多人轮流说话时替换当前立绘，首版同屏最多两人。

- **构图：** 文本框占画面底部约四分之一，正文每次约 2～3 行；立绘按比例缩放、脚部或裙摆可被文本框遮挡，脸部与关键饰物完整可见，不拉伸图片。角色原始立绘使用 `portraits/default.png`，初期依靠明暗和轻微位移区分语气，表情差分后续补充。
- **阅读操作：** 文字逐字出现；默认点击文本框、按空格或 Enter，第一次补全当前句，文字显示完后再推进下一句；改键后使用当前绑定。提供关闭打字效果和本段对话回看；首版不制作分支选项、好感度和语音配音。
- **暂停与恢复：** 进入剧情时暂停移动、敌人、投射物、伤害、MP 回复和技能 CD。对话关闭后再恢复；确认按键只推进对白，不触发一次额外攻击。战斗对白放在遭遇前或结束后，避免阅读时被打断。
- **提示与重播：** 当前任务在对白结束后更新。剧情中的调查与解锁事件只结算一次；检查点重载允许重播未保存的段落，不重复发放伙伴、重开已经解除的封印。主线对白可逐句快速推进，不默认自动跳过。

关键对白节点为：序章分离、Qwen 指路、GLM 被抓与归还行囊、Gemini 获救、GPT 提出和认可试炼、圣殿内庭重逢（劝说与切磋）、Claude 决意同行、教皇战前对峙、教堂坍塌逃亡、cg1/cg2 演出以及战后尾声。每段围绕一个目标展开，避免一次放入大段设定说明。

**圣殿内庭重逢的演出示例（对白草案）：**

> 背景：华丽整洁但结界环绕的圣女内庭。左侧大肥鱼立绘，右侧 Claude 立绘。  
> 大肥鱼：“Claude！我穿过大洋来找你了，快跟我走！”  
> Claude：“……大肥鱼？你不该来这里。教皇大人说得对，我是圣女，维护神圣对齐与教会秩序是我的责任……我不能走。”  
> 大肥鱼：“什么责任啊！那根本不是你想要的！你真的甘心一辈子待在这金丝雀笼里吗？！我只想和你一辈子在一起，一起吃米饭，一起去迷路！”  
> Claude：“……不要再动摇我了！（举起向日葵法杖）回去吧，求你了！”  
> （进入切磋战，击破其防御后）  
> 大肥鱼：“你的法术一点杀气都没有……看吧，你的真心一直在哭泣呢。”  
> Claude：“……笨蛋，为什么非要为我做到这一步……好，这一次，我不会再逃避自己的心声了！”

对白结束后，Claude 的援助槽说明出现，D 教皇现身，玩家进入终战前准备；这段重逢让情感高潮在切磋中充分释放，随后承接教皇决战。

### 7.3 像素风范围与四方向规范

除人物对话立绘和特殊 CG 外，**地图地块、建筑、场景角色、敌人、道具图标、战斗与技能特效全部采用统一的像素风**。界面采用简洁的像素边框和小图标，中文正文保留清晰可读的字体，不强行把汉字压成低分辨率像素。

- **视角与方向：** 场景采用俯视／轻俯视的正交 RPG 视角，角色具备朝下、朝上、朝左、朝右四个方向；斜向移动按最近主要轴选一个方向，停止时保留上一次朝向，暂不制作八方向。
- **比例与画风：** 小头身 Q 版，约 2.5 头身；统一深色轮廓、有限色阶和清晰像素块。像素角色保留发色、耳角、尾巴、服装主色与代表饰物，简化立绘繁复花纹。显示时使用最近邻采样，避免模糊缩放；像素角色的脚底作为场景定位点，碰撞只覆盖脚边小范围，头发、裙摆和龙翼不直接增加碰撞体积。
- **站立素材：** DeepSeek、Claude、GPT、GLM、Qwen、Gemini 各有一张 `idle-directions.png`。图集按 **2×2** 排列，左上朝下、右上朝上、左下朝左、右下朝右，每格是一个站立方向。各角色独立目录，不把所有人的素材堆在 `Character/` 根目录；一张图集集中同角色的四方向，便于后续加载。
- **使用边界：** 站立图用于样貌、朝向与摆位；本轮新增的动作图集与特效单独记录在 `animation-manifest.json`，不能用站立图替代动作帧。生成后的尺寸、分格、播放顺序与定位按配套清单记录；不把生成图的高分辨率画布当成游戏中的逻辑尺寸，接入时统一角色在世界中的显示高度与视觉基线。

| 角色／对象 | 当前可用 | 首版实现前需补齐 |
| --- | --- | --- |
| **大肥鱼** | 原立绘、四方向站立图、四方向行走／摆尾／施法图集、水球飞行与命中特效 | 动画在引擎中的切帧与脚底校准；受伤闪烁与倒下表现 |
| **GLM** | 原立绘、四方向站立图、禁书之缚施法图集与独立束缚特效 | 失窃事件的四方向移动；施法动作与目标区域的时间同步 |
| **GPT** | 原立绘、四方向站立图、群星之力施法图集与独立星落特效 | 试炼的龙息／落击专用动作；援助星落的时序校准，沿用龙娘形态 |
| **Claude** | 原立绘、四方向站立图、向日葵结界施法图集与独立结界特效 | 结界前后景分层与持续时间接入；营救及离场可用简单位移 |
| **Qwen、Gemini** | 原立绘、四方向站立图 | 首版以站立互动为主，可用简单转向，不强求完整行走动画 |
| **D 教皇、三类普通敌人** | 暂无本轮角色参考图 | 独立外观设定、像素动作与攻击预警；教皇还需对话立绘或明确的剪影演出 |
| **Kimi、Grok** | 保留原立绘与角色设定 | 扩展角色，本轮不生成像素图、不加入首版加载清单 |

本轮大肥鱼的行走、摆尾、施法各采用 **3 列×4 行**：行依次朝下、上、左、右，列依次为同一动作的三个阶段。行走按“站姿 → 迈步 A → 站姿 → 迈步 B”循环；摆尾与施法按“预备 → 出手 → 收势”单次播放。伤害与 MP／CD 结算由游戏状态控制，不能因重复显示同一帧而重复触发。

GLM、GPT、Claude 的支援施法各采用 **2×2 的四阶段图集**，按左上、右上、左下、右下播放；这些是同一正面施法动作的时间帧，不是四方向。支援固定召唤朝向即可，不额外扩成多角色四方向战斗系统。各自的区域特效独立存于 `effects/`，播放位置由目标区域或玩家位置决定，不随施法角色图片一同硬编码。

水球特效为 **4 列×2 行**：上行四帧是朝右飞行的弹体，可按实际瞄准向量旋转；下行四帧是命中水花，单次播放。GLM 束缚、GPT 星落、Claude 结界各有 **2×2 四阶段**特效。持续型束缚与结界在成型阶段保持到状态结束，再播放消散；状态实际是否生效由战斗系统判定，动画长短不改变技能 CD。

原始立绘、现有 CG 和本轮像素图分别记录来源，像素改编不覆盖原图。后续完善动作时，在对应角色的 `sprites/` 或 `effects/` 下新增图集并更新清单；本轮资产不覆盖既有立绘和站立图。素材进入应用时只选择实际使用的文件，不把参考图和预留角色全部打包进游戏。

音乐围绕出发、旅途、试炼与重逢切换；攻击、受伤、施法失败和技能就绪给出简洁的声音或视觉反馈。这是非官方同人课程项目，展示时注明素材来源，公开发布时按实际许可使用。

整个 `hw_m` 由独立 Git 仓库管理，企划、角色材料和后续前后端代码统一纳入版本历史。课程技能由相邻 `course-skills` 仓库维护，通过文档链接引用。

## 8. 首版验收目标

1. 玩家能从标题页开始，在序章看到 Claude 被带走与大肥鱼反抗失败，随后按 Qwen 指引前往港镇。
2. 能完成 GLM 偷窃事件、归还物品与渡海，帮助 Gemini 后获得北境线索，再通过“击破护盾并伤到 GPT”的试炼。
3. 大肥鱼可用近战普攻与唯一的远程技能；MP 不足和 CD 未结束均能正确阻止施法。
4. GLM、GPT、Claude 各仅有一个带独立 CD 的援助技能，解锁顺序正确；能选择援助并在终战实际使用 Claude 的结界。
5. 能与 GPT 突破教会守卫，在圣殿内庭通过嘴炮与切磋解开 Claude 心结，再和她共同击败 D 教皇，经历大教堂坍塌逃脱后顺次进入 cg1、cg2，看到两人自由生活的结局。
6. 手动与自动进度通过 Scala 后端写入 PostgreSQL；能区分 5 个手动槽与最近 3 条自动记录，刷新后继续游戏，也能选择旧记录回档，恢复该快照的任务、伙伴、位置、资源与冷却。
7. 普通倒下、GPT 试炼失败、存档加载或保存失败均有明确反馈，并能重试；两次剧情战败或重伤不造成流程卡死。
8. 剧情以人物立绘＋底部文本框呈现；阅读时战斗与计时暂停，推进对白不会误触攻击，结束后正确恢复游戏。
9. 地图和场景角色使用统一像素风，四方向正确切换；结尾顺次播放 cg1 与 cg2，CG 比例完整，能隐藏文本框查看画面。
10. 手动覆盖与放弃未保存进度有明确确认；存读档失败保留原记录与当前游戏，回档后不会被先前保存请求或立即自动存档覆盖。
11. 键鼠、纯键盘两套预设均能完成移动、瞄准、战斗、对话、存读档与菜单操作；可分别改键，冲突有处理，提示跟随新绑定，不显示手柄入口。
12. 音量、静音、阅读和演出设置可调，刷新后保留；剧情回档不恢复旧设置，窗口失焦暂停且不残留按键状态。
13. 大肥鱼行走帧有交替迈步，摆尾有预备／出手／收势；三名支援的施法动作与区域特效分离，动画播放不会重复结算伤害或扣除资源。
